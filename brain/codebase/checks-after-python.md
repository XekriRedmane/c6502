# The checks after Python

- `c6502cpp check-golden -j 12` checks the C++ compiler against golden/ (about a minute with MSVC, 40 s with GCC in WSL), and `c6502cpp check-frozen` against cpp/tests/frozen (28 s on Windows, 4 s on Linux, where writing the unpacked records is cheaper). cpp/README.md, "The checks after Python", has the formats and how to accept a change with `check-golden --update`.
- The golden files name the repository's files relative to the root, and both sides take `<root>/` out of every message. A command's argument counts as such a path only when it starts with `examples/`, `tests/`, or `golden/`, so a new job that names another directory of the root needs that list (`ROOT_DIRS` in tools/write_golden.py, `kRootDirs` in src/golden.cpp) to grow.
- check-golden runs every command line through `compile_command::run`, the code of `c6502cpp compile`, so any command line compile.py takes can be a job. A `columns <n>` step sets argparse's terminal width for the commands after it (80 before one), and tools/write_golden.py records one when a job changes `COLUMNS`. `write_golden.py --modes ""` writes only the `links` and `cli` manifests, in a few seconds.
- Capture binutils records without `C6502_CPP_BACKEND`. Since step 7 the switch sends the assembler and the linker to C++, so a run with it records only `elf_read`, `parse_metadata`, nm, objdump, and the disassembler.
- Every raising call of the links is about 70 MB of blobs, nearly all one message about an undefined symbol, so the freezer keeps one raising call per form of message. Reading a 1.5 GB capture one file at a time in one process took over 40 minutes, and a process per function with the blobs' sizes listed once takes under a minute for the binutils records and about 3 minutes for the TAC calls.
- Python on Windows refuses `threading.stack_size` of 256 MB or more (ValueError). tools/write_golden.py runs tac_sim.py in a thread of 128 MB with a recursion limit of a million, which gives the value of every corpus program where compare_tac_sim.py's main thread raises RecursionError.
- Adding a language to `project()` in cpp/CMakeLists.txt (C, for XZ Embedded) makes MSBuild rebuild every target from scratch, about 15 minutes on this machine.
