# Removing comments with Comment Sicko

- Robert ran `/pstack:no-comments` on cpp/src/binutils on 26 Nov 2026 as a pilot for all of the C++ and Python, which is about 1,200 files and 475K lines without cpp/third_party and cpp/generated. He chose the pilot over a full run. Each further directory is run only when he approves it.
- He also had the passage of ~/.claude/writing-voice.md removed that made comments the place where recorded facts live, so recording a fact is no longer a reason to keep a comment.
- Most of the comments left from the port describe the C++ by the Python it replaced, in Python names (`_StrTab`, `_split_list`), regexes for matchers written by hand, port history ("group F of step 7"), and pointers to removed files (binutils/assembler.py, passes/linker.py). They are our own code's surprises, so they go.
- Comment Sicko kept assembler.h's 17-line module comment as an API contract, though it listed the Python `str` quirks the assembler copies (`splitlines` at U+2028, digits of any script, the recursion cutoff of `kMaxDepth`). The brief for the wider run states that a comment describing the C++ by a removed Python implementation is meat, even in a header.
- Since group R of step 9 (27 Nov 2026) no Python reads anything the C++ writes, so a comment that describes a contract with compile.py, nm.py, objdump.py, cpp_backend.py, or sim/ describes code that no longer runs. A copy of Python's behavior can still be a contract with the golden files or the frozen captures, which hold the Python's output, so run `check-golden` and `check-frozen` after removing one.
- The agent's flags point at code that copies Python because the port matched its output byte for byte, such as `py_slice` in ld.cpp and `kMaxDepth`. All 12 flags in binutils were fixed on 26 Nov 2026 with no change to golden/ or the frozen captures, and the bounds checks that replaced the Python slices turned a silently grown section into an `InternalError`. A refactor that changes no output still needs tests of its edge cases, since the golden files hold only well-formed compiler output. For `split_operand`, a Python port of the old and new versions compared on 650,000 generated operands showed that the two versions agree.
- The agent took `check-binutils` (checks.cpp) for dead code because tools/capture_binutils.py, which wrote its records, is gone. `check-frozen` runs it on the records frozen in cpp/tests/frozen/binutils, so trace a check's callers in cpp/src/main.cpp before calling it dead.
- Trimming a clause out of a wrapped comment leaves ragged lines and dangling references ("that output section"), so reread each trimmed comment.
- On slice 4 of cpp/src/passes (26 Nov 2026), Comment Sicko's flag on an operand walk in `promote_loop_carried_to_a` led to two miscompiles that new doctests showed: a packed BCD add of the slot after the loop, and a call or soft-stack access in the preamble, which overwrote the value parked in Y. A flag that names a hand-written operand or register walk is worth a test before it is triaged as a style issue.
- In slice 6 of the cpp/src/passes run on 26 Nov 2026, Comment Sicko stopped at a usage limit, and a SendMessage to its agent ID after the reset let it finish and hand back its report. Its report gave 3,519 lines deleted where `git diff --shortstat` gave 2,781, so take the counts for the report from git.
- On slice 8 of cpp/src/passes (26 Nov 2026), the agent reported that it had rewrapped every trimmed comment, and about 15 were still ragged, with a short line left mid-paragraph or a line past 80 columns. Two had a dangling "So does" whose antecedent was gone. Read the diff's `+` comment lines for line length rather than trusting the report.
- Several Python-repr idioms already have a C++ helper. `asdl::constructor_name` (cpp/src/asdl/runtime.h) gives a value's constructor name, which the unroller had copied as its own `class_name`. Search the runtime before writing a fix for such a flag.
- A refactor that makes a misuse unrepresentable, such as two optional pointers merged into one struct of references, can't be shown failing by reverting it, since the tests no longer compile. Revert only the check the refactor adds, in the same turn of the build lock.
- `check_record` can't test a stage's refusal of a malformed record. `stage_checks::check` turns any exception other than a `CompileError` or an `InternalError` into `exception: <message>`, which no record's output matches, so call the stage's `run_*` function and check what it throws.
