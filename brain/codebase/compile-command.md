# c6502cpp compile and compile.py's shim

- Under `C6502_CPP_BACKEND=1`, compile.py's `main` runs `c6502cpp compile` (cpp/src/compile_command.h) through `cpp_backend.run_tool`, in frames (`C6502CPP_FRAMES=1`). The frames exist because tools/compare_backends.py sends stdout and stderr to one StringIO, so their order matters, because tests patch `sys.stdin` with a StringIO, and because Python's own streams have to do the newline translation and the encoding for the bytes to match.
- Python 3.11 on Windows reads and writes a pipe in cp1252 with CR LF. `c6502cpp compile` run by itself writes text mode (CR LF) UTF-8 and reads stdin as UTF-8, so it gives compile.py's bytes for ASCII text only.
- The shim's start, measured on 24 Nov 2026 for `-S` of a one-line program: about 92 ms (120 ms before G2), of which Python's own start is about 32 ms, compiling compile.py's source (a script isn't cached as .pyc) about 12 ms, importing subprocess (which imports locale and re) about 30 ms, and the C++ process about 13 ms. diagnostics.py imports dataclasses, which cost about 30 ms more until compile.py imported it after the early exit, and shutil about 12 ms until `cpp_backend._terminal_columns` replaced it. json costs little once re is loaded. tests/test_cpp_backend.py's `TestCommandLine.test_compile_imports_only_the_shim` keeps the list of modules short.
- Python's linker accepts any origin. `-Ttext=0x10000` writes an executable above the 6502's address space, and `-Ttext=-1` ends in `struct.error` from `elf.write`. The C++ side gives the same, through `check_write_fields`.
