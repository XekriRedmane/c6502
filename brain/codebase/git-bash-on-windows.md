# Git Bash and Python on this Windows machine

- A PreToolUse hook (~/.claude/hooks/reject-heredoc.sh, wired in ~/.claude/settings.json) denies any Bash command with a heredoc, because a heredoc through the Bash tool halved the backslashes it passed on, even with a quoted delimiter, and an edit script's replacements then matched nothing. Write a script with the Write tool and run it from its file.
- Windows Python reads `/c/w/...` as a path on the current drive's root and fails. Give Python scripts `C:/w/...`.
- No cmake is on the PATH. The system PATH is stored as REG_SZ, so its `%STM32CLT_PATH%` entries don't expand, and Robert keeps it that way. He prefers Visual Studio's cmake (3.26) to STM32CubeCLT's, so put `/c/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin` on the PATH for each command that runs cmake or ctest. A build directory configured by one cmake records its path, so configure a fresh one after switching.
- Git Bash rewrites an argument or environment value that looks like a Unix path when it starts a Windows program, so `CL=/MP` reached cl.exe as `C:/Program Files/Git/MP`. Spell a Windows tool's option with a dash where the tool takes one (`-MP`), or set `MSYS_NO_PATHCONV=1` for the command.
- `python3` is the Microsoft Store stub. Run Python with `uv run python`, from the repository's root. `uv run` takes the project of the current directory, so a command run from another directory doesn't get the project's venv with py65 and pytest.
- Don't check line endings with grep, which in Git Bash strips the CR from each line it reads unless given `-U`. A check built on it converted 38 files the wrong way and then all 90 back, and on 26 Nov 2026 a count with `grep -c $'\r$'` reported six LF files as CRLF. Check a file before editing it with `python ~/.claude/skills/exact-edits/eol.py --style FILE...`. In HEAD, docs/ is LF apart from the four `*_grammar.txt` files, and the root is LF apart from .gitignore, c99.asdl, and tac.asdl.
- Python on this machine opens a file as cp1252 unless told otherwise, so an em-dash or a "±" fails to match or is written wrongly. A script that reads or writes text names `encoding="utf-8"`, and `newline=""` when it rewrites a file in place.
- A redirected stdout on Windows writes CR LF in cp1252. Never regenerate a checked-in file (an example's `.asm`, a golden file, a generated list) by redirecting a command's output. Use the tool's own `-o` or `--update`, or have the script open its output with `encoding="utf-8", newline="\n"`, and compare its line endings with HEAD.
