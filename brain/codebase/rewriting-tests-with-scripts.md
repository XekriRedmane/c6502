# Rewriting many test modules with a script

- Edit by the AST's positions (`lineno`, `col_offset`, `end_lineno`, `end_col_offset` turned into offsets), apply the edits of a file from its end backward, and assert that no two overlap. Write the files only after every file has been processed, since a failed assertion halfway through left 69 modules rewritten in G9.
- Fix the imports by scope. A call of a plain name binds to the nearest enclosing function, or the module, whose own body imports it. Adding a new name to every `from compile import` line of a file made unused imports wherever a line imported something else, and a function-local import has to follow the calls in that function.
- Place a new module-level import after the last `Import` or `ImportFrom` node of the module's body. A line-based scan took a docstring line that began "from the carry of" for an import and put the new import inside the docstring.
- Check the result with pyflakes before and after: run `uvx pyflakes tests/*.py` on HEAD's tests (extracted with `git archive HEAD tests | tar -x -C <dir>`) and on the rewritten ones, strip the line numbers, sort, and diff. A rewrite adds no line to the diff when it is clean.
- When porting Python tests to doctest, write each C++ file as a template with markers for the Python values it needs (a module attribute, a list of `(name, source, value)` cases, or an expression evaluated in the module), and have a script fill each marker with a raw string literal of the value. In batch 4 of G1 (26 Nov 2026) this carried 61 modules' C sources into C++ with nothing retyped, and the script has to run before the Python tests are deleted, since some of the values go with them.
- A marker that names a string constant by its line, as C:/w/G4b/fill.py's `PYSTR(test_x.py:LINE)` did in G4 (27 Nov 2026), takes the file's own line numbers, which `cat -n` of several files at once doesn't give. Python merges implicitly joined literals into one constant at the first line, but `_HEADER + "..." + "..."` holds separate constants, so for such a source evaluate the whole value of the assignment from the AST in the module's namespace. The same evaluation, with a loop variable bound in the namespace, writes the programs a test method generates inside its loop, for the CRC-32 the C++ case checks, so no generator has to be retyped into the script.
- After deleting test methods, a class's private helper methods and class attributes, a module's private functions and constants, and another module's helpers that only the deleted tests imported can all be left with no reader. pyflakes reports none of them, so walk the AST for names with no remaining reference, and repeat until nothing changes.
- A rewrite can reach a test that exists to check the old form. In G9, tests of `_run_stage` given the preprocessor's output were rewritten to `_run_source` and had to be restored, so read the diff of every rewritten module before committing.
- Deleting a node by its AST span leaves behind the comment above it, since a comment isn't part of the node. In batch 3 of G1 (26 Nov 2026) the comment over `ALT_BOOL_WARNING` in test_c23_bool.py was left heading the next constant. A span that also takes the blank lines after the node removes the only separation when the line before the node isn't blank, which joined `]` to the next `def` in test_bcd_builtins.py.
- pyflakes reports unused imports but not unused module-level functions, so a helper whose last caller moved to C++ stays behind silently (`_codegen` in test_recursion_saves.py). After deleting tests, list the top-level names and class attributes that nothing in the module refers to (a short AST walk over `ast.Name` and `ast.Attribute`), and compare the list with the module at the base commit.
