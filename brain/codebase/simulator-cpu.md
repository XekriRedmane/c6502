# The C++ CPU and its checks against py65

- cpp/src/sim/cpu.h (G3 of step 9, 26 Nov 2026) executes as py65 1.2.0's `MPU` does, including py65's departures from the NMOS 6502: decimal ADC and SBC set Z, N, and V from the result before the adjustment, `DEC abs` ($CE) takes 3 cycles, the 105 undefined opcodes skip one operand byte in 0 cycles, BRK sets B in P itself, and JSR pushes its return address before it reads its target. A word read at $FFFF raises `IndexError` in py65 and throws `CpuError` in C++. Read py65's devices/mpu6502.py in the uv venv before changing any of it.
- The CPU makes its reads in py65's order, the opcode fetch included, and test_cpu.cpp checks the order of every read against py65's. A read callback replaces memory's value, and a write goes to the write callback and then to memory.
- tools/py65_cpu_vectors.py gave py65 a memory whose bytes take a random value when first read and that records each read and write. The bytes read before written are then the vector's initial memory, with the rest zero, so no list of the addresses an addressing mode touches had to be written. The whole CPU passed its 2,971 vectors on the first build.
- `C6502_SIM_LOCKSTEP=1` makes `Simulation.run` compare py65 with the C++ CPU (sim/lockstep.py), and `C6502_SIM_LOCKSTEP_LOG=<dir>` collects each run's counts. C:/w/g3/lockstep.sh, lockstep_all.sh, fuzz_lockstep.sh, and tally.py ran the suite and the fuzzers with it. The suite took about 6 minutes in three parts, against about 4 without the mode, and 3,000 fuzz seeds about 25 minutes with `-j 10`.
- One `cpu-run` request covers a whole run, each segment after a hook carrying the hook's writes as patches, since each request starts a c6502cpp process. On a difference, the mode replays py65 from the start to the instruction and runs that one segment in C++ again to show both states. A py65 with `LDA #` broken on purpose was caught at the first instruction, which showed the comparison isn't vacuous.
- For G5: the games' Python machines decode each instruction's soft-switch access before running it, and `JMP ($C0xx)` isn't decoded there, while the read callback sees it. `run` stops at BRK before calling `before_instruction`, so a machine that marks every PC it reaches turns `stop_at_brk` off.
