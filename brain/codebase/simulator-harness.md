# The C++ simulator harness and its checks

- cpp/src/sim/harness.h, runtime.h, and assembler.h (G4 of step 9, 27 Nov 2026) were ported from sim/harness.py, linked.py, runtime.py, and assembler.py, which group R of step 9 removed. The tests reach them through cpp/tests/sim_case.h (`suite::build_sim(source, optimize)`), and a module's simulator cases are in cpp/tests/test_<module>_sim.cpp. cpp/src/sim/source_sim.h compiles a source for the harness outside the test library, for the fuzzers' runner. cpp/src/sim/CLAUDE.md lists the directory's files.
- The whole runs were compared with records that an uncommitted copy of sim/harness.py wrote in a second worktree, which a doctest case built and ran again from the same state, and every one of the suite's 4,263 runs matched. The case and `c6502cpp check-sim-assembler` were removed after the comparisons passed, since neither input is in the repository and neither can be written again. A comparison meant to outlast the code it compares with needs its records frozen in cpp/tests/frozen.
- No hook call of the suite has inputs in the four cases where the Python hooks differed from fp_arith (overflow to infinity, a zero divisor, a NaN operand, a NaN or infinity converted to an integer), so decision 1 of step 9 moved no expected value, and doctest cases in cpp/tests/test_sim_harness.cpp show each case.
- cpp/CMakeLists.txt gives each case named `"shard: <name>"` a ctest entry by reading the test files with `file(STRINGS ... REGEX ...)`. A line holding a semicolon comes back as several list items, so match each item with `if(... MATCHES ...)` and `CMAKE_MATCH_1` rather than `string(REGEX REPLACE)`, which passes a non-matching item through unchanged. Writing the cases with a macro hides their names from that reading.
- The expected values that Python's models of the BCD builtins and the bit-precise types computed are frozen, as cpp/tests/frozen/sim/bitint_sim.txt is, and a generated program's case checks a CRC-32 of its sources against the one the Python generator gave. Neither can be computed again from Python, so a change made on purpose to such a value is edited by hand.
