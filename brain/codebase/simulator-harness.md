# The C++ simulator harness and its checks

- cpp/src/sim/harness.h, runtime.h, and assembler.h (G4 of step 9, 27 Nov 2026) are sim/harness.py, linked.py, runtime.py, and assembler.py in C++. The tests reach them through cpp/tests/sim_case.h (`suite::build_sim(source, optimize)`), and a module's simulator cases are in cpp/tests/test_<module>_sim.cpp. The Python harness stays until R, since the games' Python machines (sim/linked.py, sim/lockstep.py) and the compile-example skill import it, though the fuzzers' runner, its last reader in the plan, moved to C++ in G6. sim/source_sim.h compiles a source for the C++ harness outside the test library.
- The whole runs were compared without a backend mode. A second worktree at the base commit (C:/w/g4rec, `git worktree add --detach`) held an uncommitted copy of sim/harness.py and sim/linked.py whose `run` wrote a JSON line per run: the source and options or the executable's bytes, the image's CRC-32, the symbols, the hooks installed, the registers and the memory patches at the start, and the end state with a diff of memory. A case in cpp/tests/test_sim_records.cpp, with C6502_SIM_RECORDS naming the records, built each program again and ran it from the same state. The suite's 4,263 runs gave 28 MB of records, the recording run took 70 s with `-n 10`, and the C++ side checked them in under two minutes. The case and `c6502cpp check-sim-assembler`, which compared the assembler with captures from C:/w/g4asm/capture_sim_asm.py, were removed after the comparisons passed, since neither input is in the repository and neither can be written again once the Python side is gone. A comparison meant to outlast the Python side needs its records frozen in cpp/tests/frozen.
- Every one of the 4,263 runs matched on the first build, with the hooks copied from Python and again with the hooks on fp_arith. No hook call of the suite has inputs in the four cases where the Python hooks differ from fp_arith (overflow to infinity, a zero divisor, a NaN operand, a NaN or infinity converted to an integer), so decision 1 moved no expected value, and doctest cases in cpp/tests/test_sim_harness.cpp show each case.
- The comparisons found two bugs in the Python side. `SimResult.return_long` read the classic HARGS for a program whose block moved, and sim/assembler.py's slice assignment grew its image for a program past $FFFF. Both were fixed with tests before the Python tests that relied on them went.
- cpp/CMakeLists.txt gives each case named `"shard: <name>"` a ctest entry by reading the test files with `file(STRINGS ... REGEX ...)`. A line holding a semicolon comes back as several list items, so match each item with `if(... MATCHES ...)` and `CMAKE_MATCH_1` rather than `string(REGEX REPLACE)`, which passes a non-matching item through unchanged. Writing the cases with a macro hides their names from that reading.
- A model the compiler folds constants with (bit_precise.py, builtin_functions.py's BCD functions) is frozen from Python for the tests, as cpp/tests/frozen/sim/bitint_sim.txt is, and a generator of programs is ported with py_random and checked by a CRC-32 of its sources against the Python generator's.
