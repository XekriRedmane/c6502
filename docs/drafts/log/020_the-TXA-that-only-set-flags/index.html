The TXA that only set flags

A peephole's "is the flag dead?" question was the wrong question. The right one was "would re-setting it change anything?"

Project c6502 Target Apple II beam state machine Bug class over-conservative liveness check Result 1 byte, 2 cycles per TXA-before-Bxx site

A TXA that did nothing

The opening of beam_target_tick's post-hit jingle dispatch looked like this:

LDX   beam_snd_ctr
TXA
BMI   .if_end@0
LDA   beam_jingle,X
STA   __local_beam_target_tick__2
TXA
SEC
SBC   #$01
STA   beam_snd_ctr

The highlighted TXA is doing nothing useful. LDX beam_snd_ctr on the line above already sets N and Z based on the loaded value. The branch reads N. On either side of the branch the very next instruction kills A — the fall-through does LDA beam_jingle,X (loading from the table; A's previous value irrelevant), and the branch target opens with its own LDX; TXA pair (overwriting A before any read).

So this TXA's flag effect is something the LDX already produced. Its register write is into something nobody reads. One byte and two cycles down the drain, with the additional irritation of being right at the front of a hot function.

The C source that produced it is innocuous:

int8_t snd_ctr = (int8_t)beam_snd_ctr;
if (snd_ctr >= 0) {
    uint8_t pitch = beam_jingle[snd_ctr];
    beam_snd_ctr = (uint8_t)(snd_ctr - 1);
    snd_delay_up(pitch, 0x0A);
}

The cast to int8_t goes through TAC as a sign-checking read; the >= 0 test lowers to a sign-bit test on the byte, which on the 6502 is just "is N clear after a load?" — i.e. LDX; BPL or LDA; BPL. The compiler picked the LDX form (because the X-indexed load beam_jingle,X wants X anyway), and a separate path inserted a redundant TXA to "set the flag", unaware that LDX already had.

What dead_a_arith already does

c6502 has a peephole called apply_dead_a_arith_elimination whose entire job is to drop instructions that only affect A and the flags, when both are dead afterward. Its check is short:

if not _writes_only_a_and_flags(instr):
    continue
if not a_dead_at(instrs, after):
    continue
if isinstance(instr, (Add, Sub)):
    if not all_flags_dead_at(instrs, after):
        continue
else:
    if not flags_dead_at(instrs, after):
        continue
drop[i] = True

The pass cheerfully drops LDA #$00 before a JMP, ADC #$00 when its result is the dead high byte of an int-promoted uchar add, and TXA / TYA whose entire output is going to be overwritten before being read.

The TXA-before-BMI case satisfied two of three conditions and failed the third:

ConditionCheckVerdict
Writes only A + flags?Mov(Reg(X), Reg(A)) ✓pass
A dead at i+1?both arms kill A before readingpass
Flags dead at i+1?BMI reads N → flags livefail

So dead_a_arith left the TXA in place. The flag was live; the pass had no way to know that the live flag was already correct.

A different kind of dead

"Flags are dead" and "the flag side-effect doesn't matter" sound related but are different soundness arguments. The first one says nobody reads the flag before something else overwrites it, so its value is unobservable. The second says something reads the flag, but the value it would read is the same one that's already there — re-setting it to the value it already has is a no-op.

For a TXA specifically, the flag effect is "set N and Z from the byte being copied into A". That byte is whatever X holds at the moment. So the flag effect is redundant if the current N and Z already reflect X's current value.

And that's exactly what the LDX on the line above provided: LDX M sets N and Z based on the loaded value, which is X's new value. Nothing between the LDX and the TXA modifies X or the flags, so at the TXA's position the flags still reflect X. The TXA would re-set them to (X == 0) and (X & 0x80) >> 7 — values the BMI was already going to see. No change, no observation.

Same shape, different reason:

Existing dead_a_arith dropNew extension
Reason: flags are dead afterward
Soundness: nobody observes the flag the dropped Mov would have set 		Reason: flags already reflect src reg's value
Soundness: dropped Mov would have set the same value the current flags already hold

Both apply only when A is also dead — the value-side of the Mov has to be irrelevant. The new branch isn't a substitute for the flags-dead check; it's a parallel one.

The backward scan

The "are the current flags reflecting src's value?" question becomes a simple backward walk within the basic block. Start at the instruction before the TXA. Find the most recent flag-setter on the straight-line path. If that flag-setter wrote the same register the TXA reads, the answer is yes. If it wrote anything else (a different register, a memory cell), the answer is no.

Skipped along the way: instructions that don't touch N or Z at all. SEC and CLC only affect carry. STA from A doesn't touch flags. PHA and PHP don't either. These pass through the scan without disturbing the search.

Stopped at: labels, branches, jumps, calls, prologues. These are control-flow joins or opaque sequences. Crossing one means the most-recent-flag-setter could be different on different predecessors; the scan bails rather than reason cross-block. (A more aggressive version of this could do per-predecessor analysis like redundant_load does, but the within-block version catches the common shape and that was enough for the corpus.)

The scan body looks like this:

j = i - 1
while j >= 0:
    prev = instrs[j]
    if isinstance(prev, (Label, Jump, Branch, Ret, Return,
                         Call, FunctionPrologue, AllocateStack,
                         LoadAddress)):
        return False
    if not sets_flags(prev):
        j -= 1
        continue
    return _writes_reg_setting_n_z(prev, src_reg_type)
return False

The first non-neutral instruction we hit decides it. The most recent flag-setter is the one that produced the current N / Z; nothing else matters.

_writes_reg_setting_n_z enumerates the 6502 register-writing ops that set flags from the new register value — every one except TXS, which c6502 doesn't model. LDA / LDX / LDY, TAX / TAY / TXA / TYA, INX / INY / DEX / DEY, ADC / SBC / AND / ORA / EOR (always on A), ASL / LSR / ROL / ROR on a register, PLA / PLX / PLY. Each writes one of A / X / Y and sets N + Z off the new value. If the dst register matches the source register the TXA reads, the flags reflect that register's value.

For the motivating shape — LDX beam_snd_ctr; TXA; BMI .L — the scan walks one step back from the TXA, finds the LDX, asks "does this write register X with N/Z reflecting the new value?", gets yes, and the TXA drops.

Why not extend redundant_load

There's another pass that already has a lot of the machinery for this kind of reasoning. apply_redundant_load_elimination tracks which operand each of A / X / Y currently mirrors, runs a CFG-wide must-availability dataflow to propagate the tracking across blocks, and uses a z_reflects list to remember which operands' zeroness the Z flag is currently set from. Dropping a TXA when z_reflects intersects X's tracked operands would have been a natural addition there.

It would also have been wrong, in a way that took some tracing to convince myself of.

redundant_load's drop check for a register-to-register Mov requires both the source register and the destination register to currently mirror something and share at least one operand. The reasoning is "both registers hold the same value already, so the transfer wouldn't change dst". That's true for the original LDA M; TAX; TXA case — A and X both mirror M, the TXA is a no-op.

The new TXA-after-LDX case is structurally different. The destination register A doesn't currently mirror anything we can prove equal to X — A's contents are unrelated noise from before the LDX. The drop has to fire for a different reason: "dst is dead, so dst's new value doesn't matter".

The problem with stitching that into redundant_load is the dataflow. redundant_load computes its in_state[block] map once per call, walking the CFG until the must-availability lattice stabilizes. Then it walks the IR with that map and drops things based on the per-instruction state.

When it drops a TXA via the existing "src and dst mirror the same" reason, the dataflow stays correct — the dropped Mov was provably a no-op on the register state, so removing it doesn't change state.a's post-Mov contents. The pre-computed in_state[B] for the successor block still matches the IR being walked.

If we added a "drop when dst dead" branch, that invariant breaks. Consider:

LDX   M           ; X = M, flags = N/Z(M)
TXA               ; A = X = M, flags unchanged in value
BMI   .if_end
TXA               ; A = X = M (still — reason A would drop this)
TXA               ; A = X = M (also reason A)
SEC
SBC   #$01        ; reads A, computes A - 1
STA   M
.if_end:
RTS

The dataflow computes in_state[fallthrough_block] as A = [M], X = [M] — because the first TXA executed, putting M into A. The two interior TXAs see state.a = state.x = [M], share an operand, and drop by reason A. The SBC reads the A-mirror that the first TXA put there.

If we also dropped the first TXA via "A is dead at i+1" (because the next interior TXA kills A), the dataflow lies. in_state[fallthrough_block] still says A = [M], but the actual machine state has A holding whatever was in A before the LDX — garbage. The interior TXAs still drop. The SBC reads garbage. The program is broken.

The fix would be to re-run the dataflow after each drop, which is expensive, or to drop in a smaller, simpler pass that has no precomputed dataflow to invalidate. dead_a_arith is exactly that — per-instruction, no cross-block analysis, iterates locally. Adding the new reason there composes cleanly with redundant_load's reason-A drops: redundant_load runs first and removes the interior duplicates (its dataflow sees the original shape, correctly), then dead_a_arith runs and looks at the now-bare first TXA. Without the interior TXAs to "kill" A on the fall-through, A is now live there (the SBC reads it), and dead_a_arith correctly leaves the first TXA alone in that program.

For the beam_target_tick shape, where the fall-through after the BMI is LDA beam_jingle,X; STA local — A genuinely killed by a load whose target IS used — the first TXA drops as intended.

Architecture

Passes that precompute analysis state once per call (dataflow, dominators, liveness) are fragile to in-sweep mutations that would have changed the analysis. Drop-by-deadness extensions belong in passes that operate per-instruction with no precomputed state to invalidate, even when the more-capable pass has tempting infrastructure.

The second TXA, which stays

Further down the same function, there's a similar-looking shape that the new check deliberately does not fire on:

.if_end@0:
LDX   beam_state
TXA
BPL   .if_end@1
AND   #$0F
TAX
LDA   floor_y_table,X
...

Same recipe: LDX, TXA, branch on N. But the fall-through after BPL is AND #$0F, which reads A. A is live, dead_a_arith correctly leaves this TXA alone.

The TXA still looks pointless — it's only between the LDX and the branch to set flags the LDX already set. The flag part is redundant; the A-load part is needed for the AND on the fall-through. The optimal transformation would be to sink the TXA past the BPL onto the fall-through path:

LDX   beam_state
BPL   .if_end@1   ; uses N from LDX directly
TXA               ; only needed on this path, for the AND
AND   #$0F
...

That's a different transformation though — branch-sinking with per-path liveness — and the cost-benefit is small (1 byte, 2 cycles per call site at most, only on the branch-not-taken path). For now this TXA stays. The general "drop-when-dead" generalization landed; the path-sensitive sink is a different pass that hasn't been built.

A test that cascade-dropped itself

The new check needed unit tests. I wrote what I thought was a clean fixture for the headline case:

instrs = [
    Mov(src=M, dst=Reg(X)),                  # LDX M
    Mov(src=Reg(X), dst=Reg(A)),             # TXA — should drop
    Branch(cond=MI(), target=".L"),
    Mov(src=other, dst=Reg(A)),              # LDA other — "kill A"
    Label(name=".L"),
    Return(save_a=False),
]
out = _rewritten(instrs)
self.assertEqual(len(out), 5)

The LDA other was padding — meant to give the CFG walker a reason to declare A dead at the TXA's position. The TXA should drop; the LDA should stay; the result should be 5 instructions.

The result was 4.

The fixture forgot that dead_a_arith iterates locally to a fixed point in a single call. Round 1 dropped the TXA, as designed. Round 2 looked at the LDA other and noticed that A is dead after it (the Label leads to a save_a=False Return; no observer for A). flags_dead_at returned True for the same reason — no Branch reads the flags before the Return. LDA other satisfied the pass's drop criteria perfectly and was dropped.

The fix to the test was a single extra atom: a STA dst after the LDA, giving the loaded value a real consumer.

    Mov(src=other, dst=Reg(A)),              # LDA other
    Mov(src=Reg(A), dst=dst),                # STA dst — observes A
    Label(name=".L"),

With the STA, the LDA's effect is observable, dead_a_arith leaves it alone, and the length assertion lands at 6. Every padding atom in every test for this pattern needed the same treatment.

Lesson

Padding atoms in peephole tests need real consumers. An LDA used as "A-kill so the pass declares A dead at the SUT" is itself eligible for the same drop the SUT is — once the SUT goes, A becomes dead after the LDA too, and the LDA cascades out. Pair every load with a store.

What it taught

Three things, roughly ordered from most concrete to most general:

1. "Dead" and "redundant" are different soundness arguments. A peephole's drop check often phrases the question as "is the side effect observable?" — and then conflates "observable" with "dead". The two are usually the same for arithmetic ops whose output is a fresh value, but for transfer ops (TXA, TYA, TAX, TAY, and the moral equivalents in any other ISA) the flag side-effect is a function of an existing register, and "the current flag state already reflects that register" is a separate, parallel reason for the side-effect to be moot. Code-generators that produce TXA-before-Bxx shapes (and there are several paths that produce them in c6502 — sign-checks on chars, comparisons folded into branches, post-load tests) get the extra collapse for free once the pass knows to ask the second question.

2. Architecture matters in where a fix goes. redundant_load had the prettier machinery — z_reflects tracks exactly this kind of "flag reflects an operand" relationship, with a CFG-wide dataflow that would catch cross-block cases the in-block scan misses. But its dataflow is a precomputed map, and the soundness of its existing drops depends on the IR not changing under it. Adding a drop reason that does change the IR (in a way the dataflow can't predict) breaks the contract for every other drop in the same sweep. dead_a_arith, the smaller per-instruction pass with no precomputed analysis, is the safer home — even though the in-block backward scan is a less powerful version of what z_reflects already does.

3. Test padding cascades the same way the SUT does. When a peephole iterates to a fixed point, atoms used as scaffolding (loads to "kill" registers, stores to "observe" memory) are subject to the pass's own drop rules. The reflex of "throw an LDA in there to mark A as dead at the SUT" sets up a cascade: drop the SUT, now the LDA's effect is unobservable, drop the LDA, now the length assert fails by one. The fix is to give every padding atom a real consumer that survives independently — the same hygiene that makes a peephole correct on real code is what makes it ergonomic to test.

The win on this specific example is small — one TXA per call to beam_target_tick, 1 byte and 2 cycles. The interesting part isn't the numbers; it's that the check now exists at all, and applies anywhere in the corpus where a code-generator path emits a sign-or-zero-check sequence as LDX; TXA; Bxx without realizing the LDX already paid for the flag set. Several other examples in the corpus have similar shapes that this pass now handles silently.
