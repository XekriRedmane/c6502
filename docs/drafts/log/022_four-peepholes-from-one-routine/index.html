Compiler log · #022

Four peepholes from one routine

A user dropped their hand-written 6502 next to the compiler's output and asked what we could learn. The honest answer turned out to be four distinct peepholes — each addressing a different category of gap, each unlocking the next.

Project c6502 Target Apple II beam state machine Method hand-vs-compiler comparison Result 94% per-function cycle reduction; line-for-line match

Two routines, one diff

The function is beam_target_tick — one frame of advance for the Apple II "beam" enemy: tick down a post-hit jingle counter, dispatch on a state byte (attack / chase / idle), and fire the next click or seed a fresh chase. About forty lines of C; a couple of dozen instructions of 6502 in either version.

I had just shipped a small peephole that folded a four-instruction A-register decrement into a single DEX;STX. The user dropped their hand-written assembly next to the compiler's output and asked: are there any other optimizations that might be learned?

The two routines lined up reasonably well, but three sites stood out. Here's the chase-phase target check — testing whether the beam has reached the floor ceiling — in both versions:

Hand-written:

.chase:
        TAX                            ; X = floor idx
        LDY FLOOR_CEIL,X
        INY                            ; Y = FLOOR_CEIL[X] + 1
        CPY BEAM_Y
        BNE .chase_step

Compiler:

.if_end@1:
   BEQ   .if_end@3
   LDA   floor_ceil,X
   STA   __local_beam_target_tick__0
   INC   __local_beam_target_tick__0
   LDA   __local_beam_target_tick__0
   CMP   beam_y
   BNE   .if_end@4

Three instructions versus five. The hand writer noticed that Y was free, that LDY abs,X exists, that INY is a single-byte register increment, and that CPY compares directly against memory. The compiler did the same logical work routed through a zero-page byte called __local_beam_target_tick__0, paying four extra bytes and six extra cycles per evaluation.

That was one diff site. There were two others.

Three categories of difference

The other two sites, in shorter form:

Site 2 — the idle-seed branch. The compiler emitted LDX seed_floor; LDA floor_y_table,X; STA beam_y; LDA seed_floor; STA beam_state. The second LDA seed_floor was redundant: X still held that value from the earlier LDX. The hand-written version used STX beam_state directly, dropping both the redundant load and the store-through-A.

Site 3 — the dispatch. The compiler emitted LDX beam_state; TXA; BPL .chase_or_idle; AND #$0F; TAX; .... The TXA set A for the AND in the attack arm, but executed unconditionally — including on the chase and idle arms, which didn't need A. The hand writer either loaded into A first (LDA) or put the TXA after the branch.

Three diffs, three distinct kinds of pattern. Reading them in sequence suggested a classification:

  • Register choice — A vs X vs Y for a short-lived value. The hand writer notices Y is dead and uses it; the compiler routes through a ZP slot because Y isn't in the regalloc pool. Site 1.
  • Flag re-use — the prior instruction's flags already encode the condition the branch will read; the explicit transfer (TXA) is purely structural. The hand writer drops it; the compiler emits it. Site 3.
  • Cross-register equivalence — when X already holds the value being loaded into A, the load is redundant in a different sense from "A already holds it". The hand writer uses STX directly; the compiler stages through A. Site 2.

Each category had a different shape, and each suggested a different place to extend the pipeline. The four peepholes — the original DEX;STX one plus the three I'm about to walk through — landed over the next few hours.

Redirect: LDA M when X mirrors M

Start with site 2 because it has the cleanest existing extension point.

c6502 already runs a forward CFG dataflow that tracks which memory operand each of A/X/Y currently mirrors. It's called redundant_load_elimination, and its job is to drop loads whose target register already holds the source value. It tracks A, X, and Y in parallel, intersects equivalence classes at multi-pred join points, and invalidates entries on any memory write that could touch the tracked address.

What it didn't do — until now — was redirect. If A doesn't mirror M but X does, the existing pass left the LDA M alone (since dropping it would leave A holding the wrong value). But the load could be rewritten as TXA: same byte transferred, but read from a register instead of memory.

The extension is one new function — _redirect_lda_to_transfer — and a single call site in the rewriter:

if _is_redundant_load(instr, state) and _flags_redundant_at(...):
    continue                                # existing drop path
redirected = _redirect_lda_to_transfer(instr, state)
if redirected is not None:
    out.append(redirected)
    _update_state(redirected, state)
    continue
out.append(instr)
_update_state(instr, state)

The function itself is twenty lines: bail on volatile, bail if the dst isn't Reg(A), bail if A already mirrors M (the drop path will handle that), then check the X and Y equivalence classes for M and return a fresh Mov(Reg(X|Y), Reg(A)) if either matches.

Soundness is straightforward. LDA M sets N/Z to bit7(M) / (M==0). TXA sets N/Z to bit7(X) / (X==0). Under the X-mirrors-M invariant the dataflow is asserting, those are the same bits. The flag effect is preserved. A ends up holding the same byte either way.

The single-site win is one or two bytes. The bigger win comes from what runs next.

Composition

After the redirect, the IR has ...TXA; STA beam_state — and that's exactly the shape via_a_store_fold already handles: it collapses TXA-then-store to STX. The redirect produces the input that an existing pass turns into a single instruction.

So the cascade for site 2 was:

LDX seed_floor      (kept — establishes X)
LDA floor_y_table,X
STA beam_y
LDA seed_floor      → rewritten to TXA by the redirect
STA beam_state      → folded with TXA to STX by via_a_store_fold
                          → TXA dropped (dead) by asm_dead_store

Result: STX beam_state. One instruction where the compiler had three. The same redirect fired in four other example files in the corpus — every place where the regalloc had loaded a value into X for some unrelated purpose and the lowering had emitted a second LDA for a downstream store.

Sink: TXA past the branch

Site 3 — the dispatch — was the awkward one. The pattern was:

   LDX   beam_state
   TXA
   BPL   .if_end@1                  ; chase / idle arm
   AND   #$0F                       ; attack arm uses A
   TAX

The compiler loaded state into X first because the chase arm later does LDA floor_ceil,X — it wants X holding the floor index. The TXA was there to get the value into A for the attack arm's AND #$0F. The BPL reads N, which both LDX and TXA set identically.

The temptation is to "fix" this by switching to LDA-first like the hand-written version. But the chase arm immediately needs X back; you'd have to insert a TAX there. The byte count comes out the same — moving the transfer from before the branch into the post-branch arm doesn't shrink anything.

What it does change is execution. The original sequence pays the TXA's two cycles unconditionally — on every call, no matter which arm runs. The chase and idle arms get charged for a transfer they don't use.

So the peephole isn't a deletion; it's a code motion. Detect the shape, and swap:

LDX   beam_state           LDX   beam_state
TXA                          BPL   .if_end@1
BPL   .if_end@1            TXA
                                AND   #$0F

Now the TXA only executes on the fall-through (attack) arm. The taken arms skip it.

The gates: the previous instruction (LDX) must already set N/Z based on X (so the branch reads the right flags after the swap); A must be dead on the branch's target arm (or we'd lose the A := X effect on a path that observes it); and A must be live on the fall-through (otherwise dead_a_arith would have dropped the TXA entirely and we wouldn't need to move anything).

The third gate keeps this pass complementary to the existing all-arms-dead drop. Together they cover the spectrum:

A live on takenA live on fall-throughAction
nonodead_a_arith drops TXA outright
noyesthis pass sinks TXA past the branch
yesno(rare; reverse direction would be symmetric)
yesyeskeep — both arms need A

For beam_target_tick, sinking saves two cycles every frame the dispatch lands on chase or idle. Not a code-size win — but the executed instruction count drops, which is what matters for a function running at 60 Hz on a 1 MHz CPU.

Promote: temps into Y

Site 1 — the chase target computation — was the largest gap and required the most surgery.

The five-instruction shape c6502 emitted for target = floor_ceil[idx] + 1 was structural: load mem-indexed into A, spill A to a zero-page slot, INC the slot in place, reload A from the slot, compare. Each instruction was doing useful work; nothing was redundant in the local-peephole sense. The inefficiency was global: the regalloc had picked a ZP slot for the temp because Y isn't in its byte-color pool.

Y has narrower roles in c6502's IR than A or X. It's used for indirect-Y addressing ((zp),Y), for the Y-indexed forms of indexed addressing, and as the operand of CPY. The byte-granular regalloc doesn't allocate Pseudos to Y because doing so would conflict with these specialized uses unless the lifetime analysis is careful. So short-lived byte temps go to memory, even when Y is dead.

The principled fix is a Y-pivot promotion pass — an analog of loop_counter_to_x for short-lived compute-then-compare temps. That's a larger project. The pragmatic fix is a peephole that recognizes the specific post-regalloc shape and rewrites it.

The pattern is five atoms long:

[i]   LDA m,X
[i+1] STA tmp
[i+2] INC tmp        (or DEC)
[i+3] LDA tmp
[i+4] CMP n

Rewrites to three:

[i]   LDY m,X
[i+1] INY             (or DEY)
[i+2] CPY n

The gates need more care than the other two peepholes. The rewrite changes three observable things: A's value (rewrite leaves it unchanged; original sets it to m[X]+1), Y's value (rewrite sets it; original leaves it unchanged), and tmp's value (rewrite leaves it; original writes m[X]+1). Each needs a dead-after check:

  • A dead after the CMP — otherwise A's new value matters.
  • Y dead at the pattern's start — otherwise Y's old value matters.
  • tmp unused in the rest of the function — otherwise some downstream code expects tmp = m[X]+1.

The first two reuse the existing CFG-walk machinery in asm_liveness. The third is a forward scan of the function's instructions looking for any operand position equal to tmp; if none, the slot is dead.

There's also an addressing-mode constraint. LDY has an abs,X mode but no abs,Y mode — the 6502 doesn't let you read via Y into Y. So the source has to be X-indexed; Y-indexed sources skip. And CPY supports only immediate, zero-page, and absolute — not indirect-Y or indexed. So the CMP's right operand has to fit those modes.

With those gates, the rewrite saves four bytes and six cycles per occurrence. In beam_target_tick, it fires once — on exactly the diff site that triggered the comparison.

How the four compose

The four peepholes weren't independent. Each one's input was, in part, the output of the others.

The opening peephole — TXA;SEC;SBC #1;STA M → DEX;STX M — folded the four-instruction A-routed decrement into a two-instruction X-register one. Before this shipped, every other peephole in this post would have had to work around the SBC version of the decrement pattern.

The redirect — LDA M → TXA when X mirrors M — produced TXA-then-store shapes that the existing via_a_store_fold collapsed to STX. The redirect alone is a one-byte win; the cascade with via_a_store_fold turns it into a two-byte win.

The sink — moving TXA past the branch — needed a flag-setter immediately before it. The opening peephole had ensured that DEX was the flag-setter at the relevant site; the redirect had ensured that other sites preserved their LDX flag effects rather than masking them with a transfer.

The promotion — five atoms to three — needed the IR to be in the exact post-regalloc shape it lands in. If round_trip_load_drop had collapsed the STA tmp; LDA tmp round-trip first, the five-atom pattern wouldn't have existed and the promotion couldn't have matched.

Ordering inside the fixedpoint loop mattered. The DEX/STX peephole had to run last, so that the upstream collapsers could turn through-temp routing into direct-destination shapes before it pattern-matched. The promotion had to run after the post-coloring shape had stabilized. The sink had to run after dead_a_arith had had a chance to drop fully-dead TXAs.

One pass produced patterns the next consumed; the next produced patterns the one after that consumed. The whole thing converged in two or three iterations of the outer fixedpoint loop.

Line-for-line

With all four peepholes in the fixedpoint, the final compiler output for beam_target_tick's chase branch:

.if_end@1:
   BEQ   .if_end@3
   LDY   floor_ceil,X
   INY
   CPY   beam_y
   BNE   .if_end@4
   TXA
   ORA   #$F0
   STA   beam_state
   RTS

And the hand-written:

.chase:
        TAX
        LDY FLOOR_CEIL,X
        INY
        CPY BEAM_Y
        BNE .chase_step
        TXA
        ORA #$F0
        STA BEAM_STATE
        RTS

Same instructions, same operands. (The compiler skips the leading TAX because the dispatch already had X = state from its LDX; the hand-written version's dispatch took a different path that needed the explicit TAX. Net: same atom count.)

For the idle-seed branch and the dispatch arm shape: same story. The final output and the hand-written reference are byte-for-byte identical in chase and idle; the dispatch differs by one byte (compiler uses LDX-then-TXA-where-needed; hand uses LDA-then-TAX-where-needed) but matches in atom count.

The optimization-relevant slice went from 356 to 323 cycles, a 9.3% reduction on a function that was already heavily optimized. Versus the unoptimized baseline, it's a 94% reduction.

The lesson

The pattern worth remembering is the classification. When a hand-written 6502 routine beats the compiler, the win almost always falls into one of three buckets:

  • Register choice. The hand writer used the right physical register for the value's lifetime — often Y, which is invisible to the regalloc. Fix shape: a targeted promotion peephole that recognizes the post-coloring ZP-routed sequence and rewrites it to register-arithmetic, OR an extension to an existing equivalence tracker.
  • Flag re-use. A prior instruction already set the flags the branch will read; the explicit transfer or compare is structural overhead. Fix shape: a backward scan that recognizes the flag-equivalence and drops or moves the transfer.
  • Addressing-mode awareness. An operation has a register-direct opcode (INY, DEX, CPY) that doesn't appear in the lowering because of (1). Fix shape: same as (1) — once register choice is right, addressing-mode awareness follows.

Each category implies a different place to extend the pipeline. None of them required reaching back into the regalloc or the IR design. Each was a few hundred lines of code in a focused peephole module, with the existing infrastructure (CFG dataflow, liveness helpers, fixedpoint convergence) doing the heavy lifting.

And the answer to "are there any other optimizations that might be learned" turned out to be: yes, if you ask the diff to classify itself.
