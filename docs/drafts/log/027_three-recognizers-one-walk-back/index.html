Three recognizers, one walk-back

Setting out to dedup three near-identical addressing-mode recognizers, I found each carried not one implementation but two — frozen at three different stages of a migration nobody finished.

The chain all three match

c6502 has three TAC passes that turn pointer-arithmetic-plus-load/store into a single 6502 addressing mode. They all key off the same upstream shape. After the front end lowers arr[i] for a 1-byte index, you get a three-instruction chain:

%ext  := ZeroExtend|SignExtend(idx_var)     # 1-byte idx promoted to int
%addr := Binary(Add, base, %ext)             # pointer arithmetic
Load(%addr, dst)  /  Store(src, %addr)

What base is decides the addressing mode:

PassbaseEmits6502
recognize_indexed_loadConstantIndexedConstLoadLDA $C,X
recognize_indexed_storeConstantIndexedStoreSTA $C,X
recognize_indirect_indexedpointer VarIndirectIndexed*LDA ($zp),Y

The walk-back from the Load/Store to the extend — %addr → Binary(Add) → %ext → ZeroExtend — plus the soundness gates (the temps must be single-use, SSA-renamed; the index must be a 1-byte type) is line-for-line identical across all three. That's the duplication I went in to remove.

The twin you inherit

Opening the files, the duplication was worse than three-way — because each pass contained two implementations of itself.

There was an older, loop-based free function (recognize_indexed_load(fn, symbols=…)) that scanned the instruction list, called a _try_recognize helper, and rebuilt the list dropping the matched defs. And there was a newer DefUsePass subclass — the framework base for SSA def-use-chain peepholes — that did the same recognition through env.def_of(var) walk-backs. The pipeline used the class. The free function was the fossil.

The interesting part: the fossil was at a different stage of decay in each file.

Three states of one migration

load — free function fully dead: nothing called it, not even a test.
store — free function test-only: the unit tests still drove _try_recognize, while the pipeline drove the class.
indirect — already converged: the free function was a one-line wrapper delegating to the class.

This is what a half-finished migration looks like once it's been sitting long enough that the surrounding code moved on. The indirect pass shows where the other two were headed; store shows why it stalled (its tests pinned the old path); load shows the cost of stopping (a dead 90-line function nobody noticed). A grep for "duplication" would have flagged the three-way overlap. It would not have flagged that each file's two copies needed to be collapsed to one before the cross-file dedup even made sense.

One walk-back

The consolidation is a shared module, extend_add_chain.py, with a single recognizer:

def recognize_extend_add_chain(addr_var, env, ctx) -> ExtendAddChain | None:
    # symbols present; addr_var SSA-renamed and single-use
    binary = env.def_of(addr_var)
    if not (isinstance(binary, Binary) and isinstance(binary.op, Add)):
        return None
    base, ext_var = _split_extend_operand(binary.src1, binary.src2, env)
    # ext_var SSA-renamed and single-use; its def is an extend
    ext = env.def_of(ext_var)
    idx_var = ext.src
    if not is_1_byte_var(idx_var, ctx.symbols):
        return None
    return ExtendAddChain(base=base, idx_var=idx_var,
                          addr_var=addr_var, ext_var=ext_var)

Each pass shrinks to: call the helper, post-check base's kind, emit its node. The load pass, in full:

chain = recognize_extend_add_chain(m.bindings['addr_var'], env, ctx)
if chain is None or not isinstance(chain.base, Constant):
    return None
addr_value = chain.base.const.value
if not (0 <= addr_value <= 0xFF00):          # C+255 ≤ $FFFF
    return None
return Rewrite(
    replacement=IndexedConstLoad(address=addr_value, index=chain.idx_var,
                                 dst=load_dst, ...),
    drop_defs=(chain.addr_var, chain.ext_var),
)

The three byte-width predicates (is_1_byte_var, is_1_byte_val) that had been copy-pasted into all three files moved into the same module. They had already drifted once before — a recurring hazard worth its own treatment — so a single home matters.

Unifying the split

The one genuine divergence was how each pass pulled the two Add operands apart. The absolute,X recognizers used a _split_const_var (one operand is the Constant base, the other is %ext). The indirect recognizer used _split_var_var (both operands are Vars; the one defined by an extend is %ext, the other is the pointer).

Both collapse into one rule once you state it right: of the Add's two operands, the one whose def is an extend is %ext; the other is base.

def _split_extend_operand(a, b, env):
    if _defined_by_extend(b, env): return a, b
    if _defined_by_extend(a, env): return b, a
    return a, None

For the const case, base comes back a Constant; for the indirect case, a pointer Var. The caller's isinstance(chain.base, …) post-check is what was previously baked into the two different splitters. The const recognizers reject a Var base (defers to nothing — it just doesn't fold); the indirect one rejects a Constant base (that's the absolute,X case, already handled upstream). Same outcomes, one splitter.

Not a RuleSet job

The previous two consolidations in this codebase merged passes onto a table-based RuleSet — a list of (pattern, guard, build) rules applied over an instruction window. The obvious question was whether the recognizers should go there too. They shouldn't, and the reason draws the boundary cleanly.

RuleSet matches an adjacency window — N consecutive instructions. The recognizers don't. They match one use site and then walk backward through the SSA def-chain, which can span arbitrary distance.

That backward walk is exactly what the DefUsePass base exists for: it hands the rewrite an env.def_of(var) and an atomic Rewrite(drop_defs=…). Forcing the recognizers onto RuleSet would mean teaching RuleSet about def-chain walks and eager def-dropping — reinventing DefUsePass inside it. The right consolidation for a family of def-chain walks isn't a shared base class; it's a shared recognition function they all call. Same instinct as the table-merge, one rung lower: extract the common procedure, leave the framework base alone.

Eager drops, one contract

Unifying surfaced a behavioral inconsistency. The indirect pass returned Rewrite(drop_defs=(addr, ext)) — dropping the two now-dead intermediate instructions in the same rebuild. The absolute,X classes returned a bare replacement and left the dead defs for a later dead-store-elimination sweep.

Both converge to the same fixed point, so in the pipeline it never mattered. But the store unit tests asserted the three instructions collapse to exactly one — which only holds if the drop is eager. That assertion was quietly testing the old _try_recognize path's immediate-drop behavior. Pointing the free function at the class meant the class had to drop eagerly too. So all three now return Rewrite(drop_defs=…): one drop contract, and the test that used to pin a dead code path now pins the live one.

What it taught

The dedup itself was unremarkable — extract a function, call it from three places, delete the copies. Net −226 lines, every test green, generated assembly byte-identical. The lesson was upstream of that.

  • Duplication in a migrating codebase hides as half-finished transitions. Before deduping across files, check whether each file has already been deduped within itself — a live implementation and a fossil of the previous one.
  • A test that drives a dead path is a tripwire. The store tests looked like they exercised the pass; they exercised its fossil. Redirecting them to the live class was the real fix, and it forced the drop-contract unification that made the three passes genuinely uniform.
  • Match the consolidation to the shape. Drifted helper copies want a canonical home; parallel window-passes want a table; a family of def-chain walks wants a shared recognition function on the base they already share. Three different shapes, three different tools — reaching for the wrong one is how a framework grows a second job.
The fossil shows you where the code was going. Finishing the trip is usually the cheapest cleanup on the table.
